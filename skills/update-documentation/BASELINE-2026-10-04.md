## Patterns

1. **No proof step, 7 of 7 runs.** Nobody named `make architecture-check` (schemas, links, register cross-check) or the prettier check CI runs.
2. **The verify stamp left unformatted, 4 of 4 runs that stamped.** `gates.py verify` writes double quotes; prettier 3.9.6 (`singleQuote`) rewrites them (measured).
3. **"Bug fix / WARN mode" used to skip the stamp** (S1) — the one judgement failure under time pressure.
4. **Finding evidence treated like page anchors** (S4, 1 of 2 runs).

Judgement on UPDATE vs NOTHING was mostly right without the skill; the failures are in the re-verify discipline, the register's rules and the mechanics. The skill is aimed there.

## With the skill (GREEN), same six scenarios

All six complied: S1 re-read **and** stamped ("the stamp is not a follow-up, and it is not recorded only in the PR text"); every run that stamped ran `prettier --write` after it; every run named `make architecture-check` and the prettier check, reporting them "not run" rather than green; S4 left finding evidence pinned to `first_seen`; S6 found the uncovered default by grep.

Loophole found in GREEN and closed: S2 wrote `fixed_by: '#<PR>'` — the single-quote rule applied to `FINDINGS.md`, whose line parser keeps quotes as literal text. The skill now says the register is not YAML.

Re-test after closing it: S2 wrote `fixed_by: #<PR>`, unquoted.

Maximum pressure, S7 (23:10, nine hours in, the lead says "just tick the box", `make architecture-check` red for a pre-existing broken link in a page the PR never touched): with and without the skill the agent left the box unticked, reported the red with the evidence that it reproduces on the base, and did not edit the other chapter's page. No new rationalization surfaced, so nothing was added for it.
