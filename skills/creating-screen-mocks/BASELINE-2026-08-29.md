# RED — a measured baseline, 2026-08-29

**The failing test for this round of edits was a real agent run, not a constructed
scenario.** An agent (Claude Opus 5, in a live session with the human present)
was asked to build a mock, invoked this skill at v1.0.3, followed it, and
produced a mock the human could not point at. What follows is what it actually
did, verbatim where possible, because the fix has to answer *these* failures and
not a guess at what an agent might do.

---

## Failure 1 · The review loop was never wired — and this is the whole point of a mock

The agent's `vite.config.ts`, as written:

```ts
export default defineConfig({ plugins: [react(), tailwindcss()] });
```

No `sourceStamp()`, no `selectSink()`. `main.tsx` never imported
`select-client`. So: zero elements stamped, no `/__select` endpoint, and
`current-selection.json` never existed.

**The human's reaction is the measurement that matters:**

> *"so my first question why doenst poiint to click work taht we have build
> togehter with te ux skill. i know that we ahve buidl the machinery so that i
> coud now click on teh moick highlight elelmetns and you woudl be able to read
> them . We tested thsi and it worked brilliantly. why doens thta work now?"*

**Why it happened — structural, not carelessness:**

- "Wire the review loop" was the **last subsection of Phase 5**, the longest
  phase, after *where to put it*, *imports*, *data-testid*, *components and
  tokens*, *the index page* and *make it clickable*. By the time an agent reaches
  it, it has been building for a while and is reading the phase as finished.
- It is **three lines and reads as optional tooling** — "copy X in and register
  both plugins". Nothing said the mock is not a mock without it.
- Phase 4 already said the variants need it wired first — but that instruction
  lives in Phase 4 and the doing lives at the bottom of Phase 5, so the ordering
  has to be reconstructed by the reader.

## Failure 2 · Phase 6 could not detect Failure 1 — the gate was blind

All five Phase 6 boxes pass on a mock with no review loop:

| Phase 6 check | passed without the loop? |
|---|---|
| typechecks against installed DS | ✅ |
| positive-control the typecheck | ✅ (agent did this, TS2322, restored) |
| no invented components | ✅ |
| real interactive elements | ✅ |
| run locally and show in a browser | ✅ — screenshotted, looked right |

**A verification phase that cannot fail on the single most important omission is
not a gate.** The agent finished, presented, and believed it was done.

## Failure 3 · The workspace was re-invented, and three parts were got wrong

The skill says "a self-contained workspace" and supplies no scaffold, so the
agent hand-wrote `vite.config.ts`, `tsconfig.json`, `index.html`, `main.tsx`,
`mock.css` and the CSS token wiring. Three went wrong:

1. **Wrong worktree.** Built in the repo's main worktree, which was 30+ commits
   stale and did not contain the feature at all. The token import resolved to
   nothing and Vite threw
   `Can't resolve '../../../../frontendV2/src/features/business-analytics/styles.css'`.
   Cost: a full move of the workspace to the feature branch.
2. **`node_modules`.** No guidance. The agent worked out on its own that it must
   symlink the app's (an install would have been slow, and this repo shares one
   `node_modules` across worktrees by symlink, so an install could corrupt
   siblings).
3. **`tsconfig` + the vendored loop.** Including `review-loop/` in the typecheck
   demands `@types/node`, which was not present and could not be installed. Six
   `TS2307`/`TS2591` errors. Resolved by scoping `include` to `src` — correct,
   but rediscovered from scratch.

## Failure 4 · The `isTrusted` guard read as a broken loop

After wiring, the agent tried to verify the round trip by scripting a click:

```js
bar.dispatchEvent(new MouseEvent('click', {...}))   // → nothing happened
```

Nothing was written. The guard is deliberate and correct —

```ts
if (!e.isTrusted) return;   // scripted clicks must not clobber the reviewer's selection
```

— but it is documented *inside `select-client.ts`*, which an agent that merely
copies the file never opens. **An agent hitting this without knowing will
conclude the loop is broken and start debugging working code.** This one was
caught only because the agent went and read the client source.

## Failure 5 · A false green while checking the server was up

The readiness check used `127.0.0.1`; Vite binds `localhost`. The check failed,
the `||` branch printed the Vite banner, and the agent read the banner as
success. Not this skill's fault, but the scaffold can remove the opportunity by
printing a URL that is known to answer.

---

## What GREEN must look like

An agent following the revised skill:

- cannot have an unwired workspace, because it does not write one
- cannot pass verification with the loop missing, because a script says so
- does not rediscover the `node_modules`, `tsconfig` or worktree answers
- is told about `isTrusted` **before** it tries to script a click

The two shipped scripts are the mechanism; the prose changes only aim the agent
at them. Prose alone produced this baseline.
